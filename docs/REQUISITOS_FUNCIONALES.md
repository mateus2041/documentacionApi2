# Requisitos funcionales

Los requisitos siguientes son una reconstrucción de la implementación actual. Las entradas y salidas corresponden al contrato observable en `src/routes/index.js`, controladores y servicios.

| ID | Nombre | Descripción detallada | Actor | Entrada | Proceso | Resultado esperado | HU | Implementación |
|---|---|---|---|---|---|---|---|---|
| RF-001 | Iniciar sesión | Valida credenciales, estado de usuario y emite JWT con id/rol. | Usuario | JSON `usuario`, `password`. | `authService.login` compara el hash con bcrypt y firma el JWT. | HTTP 200 con `token` y perfil sin contraseña; 400/401/403 ante errores correspondientes. | HU-001 | `POST /auth/login`; `src/controllers/authController.js`, `src/services/authService.js` |
| RF-002 | Consultar perfil | Devuelve la identidad del usuario autenticado. | Usuario autenticado | Bearer JWT. | Middleware valida token y controlador proyecta campos públicos. | HTTP 200 con id, usuario, nombre y rol. | HU-001 | `GET /auth/perfil`; `src/middlewares/auth.js`, `src/services/authService.js` |
| RF-003 | Listar sorteos | Lista sorteos opcionalmente filtrados por tipo y estado. | Usuario autenticado | Query `tipo`, `estado`. | Filtra colección en memoria. | HTTP 200 con arreglo (vacío si no hay coincidencias). | HU-002 | `GET /sorteos`; `src/controllers/sorteoController.js`, `src/services/sorteoService.js` |
| RF-004 | Consultar sorteo | Busca sorteo por id numérico. | Usuario autenticado | Path `id`. | Convierte id y busca en memoria. | HTTP 200 con sorteo o 404 si no existe. | HU-002 | `GET /sorteos/:id`; `src/services/sorteoService.js` |
| RF-005 | Crear sorteo | Crea sorteo CHANCE/BALOTO con fecha futura y datos validados. | ADMIN | JSON `tipo`, `nombre`, `fecha`, `acumulado` opcional. | Valida y asigna id; comienza ABIERTO, sin resultado. | HTTP 201 con el sorteo; 400 con datos inválidos; 403 si no es ADMIN. | HU-002 | `POST /sorteos`; `src/services/sorteoService.js` |
| RF-006 | Registrar resultado | Valida resultado según tipo, marca sorteo JUGADO y liquida tiquetes ACTIVO asociados. | ADMIN | Path `id`; JSON `resultado` (cadena Chance u objeto Baloto). | Obtiene sorteo, valida, calcula premios y registra hora. | HTTP 200 con sorteo actualizado; 404/409/400 según error. | HU-002 | `POST /sorteos/:id/resultado`; `src/services/sorteoService.js`, `chanceService.js`, `balotoService.js` |
| RF-007 | Vender Chance | Registra tiquete con 1–5 apuestas validadas y total calculado. | VENDEDOR | `sorteoId`, `apuestas`, `cliente` opcional. | Comprueba sorteo y ventana, valida apuestas, genera código y guarda en memoria. | HTTP 201 con ticket CH-, estado ACTIVO y total; errores 400/403/404/409. | HU-003 | `POST /tickets/chance`; `src/services/ticketService.js`, `chanceService.js` |
| RF-008 | Vender Baloto | Registra tiquete con 1–10 jugadas manuales o aleatorias. | VENDEDOR | `sorteoId`, `jugadas`, `cliente` opcional. | Comprueba sorteo/ventana, valida jugadas, calcula total y guarda. | HTTP 201 con ticket BL- y estado ACTIVO; errores 400/403/404/409. | HU-004 | `POST /tickets/baloto`; `src/services/ticketService.js`, `balotoService.js` |
| RF-009 | Listar tiquetes | Filtra por fecha/estado; limita vendedores a sus propios tiquetes y permite al ADMIN ver todos. | Usuario autenticado | Query `fecha`, `estado`. | Aplica rol y filtros sobre datos en memoria. | HTTP 200 con arreglo. | HU-005 | `GET /tickets`; `src/services/ticketService.js` |
| RF-010 | Consultar tiquete | Busca por código y añade resumen del sorteo y condición de ganador si se jugó. | Usuario autenticado | Path `codigo`. | Busca tiquete y sorteo; determina `ganador` o null. | HTTP 200 con tiquete enriquecido o 404. | HU-005 | `GET /tickets/:codigo`; `src/services/ticketService.js` |
| RF-011 | Anular tiquete | Anula tiquete activo con motivo, aplicando propiedad/rol, estado, sorteo y ventana temporal. | VENDEDOR propietario o ADMIN | Path `codigo`; JSON `motivo`. | Valida reglas y agrega metadatos de anulación. | HTTP 200 con estado ANULADO; 400/403/404/409 según causa. | HU-006 | `POST /tickets/:codigo/anular`; `src/services/ticketService.js` |
| RF-012 | Pagar premio | Registra pago de premio disponible y actualiza estado; rechaza duplicado o vencido. | VENDEDOR | Path `codigo`; Bearer JWT. | Valida sorteo, estado y caducidad; crea pago en memoria. | HTTP 200 con pago; errores 403/404/409/410. | HU-007 | `POST /tickets/:codigo/pagar`; `src/services/ticketService.js` |
| RF-013 | Consultar resumen de caja | Calcula movimientos de una fecha para el vendedor autenticado; ADMIN puede indicar `vendedorId`. | VENDEDOR o ADMIN | Query opcional `fecha`, `vendedorId`. | Agrega ventas válidas, anulaciones, premios pagados y cierres. | HTTP 200 con cantidades, totales, saldo y bandera `cerrada`. | HU-008 | `GET /caja/resumen`; `src/controllers/cajaController.js`, `src/services/cajaService.js` |
| RF-014 | Cerrar caja | Registra el efectivo reportado y diferencia con saldo, una sola vez por vendedor/fecha. | VENDEDOR | JSON `efectivoReportado`, `fecha` opcional. | Valida monto, consulta resumen y crea cierre. | HTTP 201 con cierre y estado CUADRADA/SOBRANTE/FALTANTE; 400/409 si inválido/duplicado. | HU-008 | `POST /caja/cierre`; `src/services/cajaService.js` |
| RF-015 | Comprobar salud HTTP | Expone estado y hora del proceso web. | Cliente/monitor | Sin parámetros ni autenticación. | Responde directamente desde Express. | HTTP 200 con `estado: "ok"` y `hora` ISO. | HU-009 | `GET /health`; `src/app.js` |

### Alcance de las respuestas de error

El middleware común traduce errores `AppError` al estado configurado, JSON mal formado a HTTP 400, rutas inexistentes a HTTP 404 y errores no controlados a HTTP 500 con mensaje genérico. La asignación de códigos indicada arriba se deriva de las validaciones del código, no de una garantía de que cada rama haya sido probada.
